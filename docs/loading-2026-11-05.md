# Branded first-load screen

Halk Büfe opens with its existing logo, a branded takeaway cup drawn with CSS, a light steam effect, and the Tavuk şiş plate already used in the hero. The plate uses the hero's identical responsive image candidates and sizes so the browser can reuse the same selected asset. There is no added generated photo or photo payload.

The screen follows the existing light/dark theme and TR/RU/EN/DE language selection. It exits as soon as both the menu and hero are ready, with a 160ms fade and no minimum display duration. Reduced motion removes the fade and decorative animation. No focus is moved.

Failure handling:

- Hero load or error resolves the image wait.
- The external controller removes the screen after 2600ms if startup never reports ready.
- A separate inline watchdog removes it after 2800ms even if the external controller fails to arrive. Normal cleanup cancels that watchdog.
- CSS includes an additional visibility guard, and a noscript style hides the splash when JavaScript is disabled.
- Page departure or back/forward restoration removes the screen immediately. The normal screen catches pointer input to avoid accidental taps on food controls underneath it; pointer handling ends when the fade starts.

Validation on 2026-11-05:

- 7 lifecycle tests passed: menu/image order, cached readiness, image error, reduced motion, timeout, history restoration, language/storage fallback and independent inline removal. JavaScript syntax and diff whitespace checks passed.
- Held component previews checked at 320×568 light, 390×844 dark and 568×320 landscape. These intentionally omit auto-dismiss so the actual loading artwork can be inspected; they are temporary QA files and are excluded from publication.
- At 320px the splash bounds are exactly 320×568, with a 284px content column; the branding and plate assets loaded.
- Normal menu navigation showed the startup screen, then removed it; all 44 dish cards rendered and the kids filter worked.
- A browser fixture with no external loader/app script removed the splash through the inline watchdog. The CSS-animation-only fallback was not independently confirmed by this browser; it is not relied on for the verified JavaScript failure path.

Real iOS/Android browser chrome and assistive-technology testing were not performed. The loading screen does not reappear on category changes, likes, basket changes or theme switches within the same document.
